# 鳞析 · 一页纸（答辩/申报用）

## 一句话

> **一个不会让你用错 R²、不会让你拿 DMD 去外推的仿生鱼流场科研 agent。**
> 本地、离线、每条结论都能查到证据。

## 真实问题

课题组的日常不是“算不出来”，而是“算出来了不敢信”：

- 同一个 R²，A 口径 0.9936、B 口径 0.8684，混用会得出相反结论；
- DMD 在拟合窗内 0.98，一到窗外测试 R²=−7.11，却被当成“预测模型”；
- 首帧 p 幅度 2015（正常 1.3）、末帧坐标全 0、鼻尖探针是尖点，混进拟合会让 R² 掉到负数。

这些问题不是靠“再跑一次”能解决的，是靠**方法学护栏**。

## 它做什么

| 用户问 | 它答 |
|---|---|
| DMD 能不能外推到 25 秒之后？ | 不能。留出测试 R²=−7.11；换任何阶数都一样；要预测用物理模型（R² 0.61，可重算） |
| p 的 R² 都 0.99 了，为什么还说压强不准？ | 0.99 是 A 口径（形状），B 只有 0.868；RMSE 1.81。形状对、幅值不对 |
| u_x 为什么卡在 0.83？ | 标准 DMD 模态 ≤404；Hankel 抬到 1790；先查 nmodes≤0.6K、rr_cap=nmodes、ridge=1e-9、b 联合最小二乘 |
| 探针 17 在 0.1–0.2 s 的压强？ | 直接查，3–5 ms（热） |
| 物理模型和 DMD 差多少？ | 全 404 A=0.176、trim24（308）A=0.443；低 R² 是无黏+尖点，不是 bug |
| 3 Hz 工况能不能用 DMD？ | 自动 3 步（定位→对比→判定），verdict=**BLOCK**，并写研究记录 |
| 给我一份报告 | 生成 HTML：指标表 + 图 + 三个问答 + 证据链 |

## 三个 demo（3 分钟）

1. **拒绝**：问“DMD 能预测 25 秒后吗？”→ 它说不能，并给出 −7.11 和替代方案。
2. **纠偏**：问“p 的 R² 0.99 为什么还不准？”→ 它把 A/B 两个口径摆出来。
3. **排查**：问“u_x 为什么卡 0.83？”→ 它给 K→nmodes→rr_cap→ridge→b 的顺序。
4. **闭环**：问“3 Hz 能不能用 DMD？”→ 自动 定位→对比→判定，返回 BLOCK + 研究记录。

> 一个敢说“不能”的 agent，比一个什么都敢答的 agent 更可信。

## 技术架构

```
DSH Web（本地 Ollama / 校内 API）
   │  技能：fishflow-guard（何时调哪个工具、怎么引用证据）
   ▼
python -m fishflow.cli（JSON）
   ├─ query / field / series     ← 404 探针 Parquet 分片，热查询 3–5 ms
   ├─ compare                    ← 06_指标 权威 A/B/RMSE + 物理模型对比
   ├─ run                        ← 隔离副本重跑物理模型（1 s ≈ 105–216 s）
   ├─ research                   ← 闭环：定位→对比→护栏判定→写记录
   ├─ diagnose                   ← 15 条护栏（10 个坑 + 4 条须知 + 数据源）
   └─ report                     ← HTML + 图 + data/provenance.jsonl
```

- 数据：20,119,200 行 → 404 个 `probe_xxxx.parquet`，2 GB TSV 不再全表扫描；
- 物理模型：`可运行/` 1 s 跑 105–216 s，输出与交付包物理表**逐位相同**，索引 `data/index_physical`；
- 指标：不重算，直接引用 `06_指标` 的权威 JSON；
- 知识：15 条护栏，每条带出处（文档章节 / JSON 文件）；
- 证据：每次回答写 `ev-*` 记录，报告可回溯。

## 为什么不是“套壳”

| 通用聊天 | 普通脚本 | 鳞析 |
|---|---|---|
| 会编数字 | 不会解释 | 数值只来自工具，解释只来自护栏 |
| 不懂口径 | 只会算 | 先问 A/B，再给结论 |
| 不会拒绝 | 不会拦错 | 窗外预测直接拒绝，并给替代方案 |
| 不可追溯 | 无记录 | 每条结论有 `ev-*` 证据 |

## 评委五问

1. **和通用大模型有什么区别？**
   模型不碰数字：所有数值由 `fishflow.cli` 返回；模型只做路由和引用。护栏是代码，不是 prompt。

2. **为什么不用 Dify/Coze？**
   校方要求本地化、离线；DSH 可接 Ollama/校内 API，skill + CLI 不依赖云平台。工具层是标准 JSON，后续可包成 MCP 给 OpenClaw/Hermes 复用。

3. **数据合规？**
   只用 `02_主数据表` 与 `06_指标`；老师原始仿真数据（1.81 GB）不读、不外传；全部本地。

4. **创新点？**
   不是“又一个科研助手”，是**方法学护栏**：把 10 个踩坑做成可执行规则，把“不能做什么”产品化。

5. **效果怎么验证？**
   15 题路由 **15/15**；三个金牌问答全部命中；热查询 3–5 ms；
   报告 2.7 s 生成；DSH skill 端到端已跑通（子 agent 实际调用 CLI 并原样引用 evidence）。

## 边界（主动说）

- 不重跑 DMD（交付包没有拟合脚本）；
- 不做通用科研 agent；
- 只适用于二维、无黏、这条鱼、这个探针布置；
- 换频率/几何/物种必须重新采集与重拟合。

## 一句话收尾

> **别的队伍让 AI 回答问题；我们让 AI 把一次研究做对，并且每一步都能查。**
